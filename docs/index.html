Regression tests for LLM agents

Change a prompt. Know what broke before you merge.

LLM agents rarely fail loudly. A tidier prompt or a cheaper model can make your agent skip a tool, give vaguer answers or crash, and code review won't catch it. agentreg replays real agent runs on every pull request and shows you what changed, case by case, in a comment on the PR.

Why two layers

Each layer catches a bug the other one misses

Rule-based checks are cheap and exact, but they can't tell a vague answer from a good one. An LLM judge reads for quality, but it gave full marks to answers made without the legal research. You need both.

How it works

Snapshot testing, built for agents

Works with any LangChain or LangGraph agent, with no changes to its code. You record a good run once and agentreg turns it into a test case that it replays on every pull request.

Record

Run the agent once. A LangChain callback captures every LLM call and tool call, with tokens, cost and latency.

agentreg record "healthcare"

Capture

The run becomes an editable YAML test case. Required tools and budgets are filled in from the recorded run.

expect:
  required_tools: [legal_risk_checker, …]
  max_tokens: 2714

Replay

Every case runs 3 times. Tool outputs can be served from the recording, so you test your change and not today's API responses.

agentreg run --tools stub --repeats 3

Report

One comment on the pull request, updated on every push, and a failing check when something regressed.

✅ passed   ❌ regressed
⚠️ flaky    ⬆️ improved

Design decisions, backed by data

Built to be trusted in CI

Majority vote over repeats

Even the unchanged agent skipped a required tool in 4 of 40 runs. With one run per case across 5 cases, roughly 4 PRs in 10 would get a red build for no reason.

A judge that grades against evidence

The first version compared two answers side by side and mostly picked whichever came first. Now it grades one answer at a time against yes/no criteria, using that run's own tool results as evidence.

Intended changes are one command

agentreg run --accept makes the latest run the new reference, like updating snapshots in Jest. Reviewers see the change as a YAML diff.

Cost is a test result too

Tokens, cost and latency are compared with the reference for every case, so a model swap shows exactly what it saves and what it breaks.

Quickstart

Try it on the demo agent

Then break it on purpose: remove legal_risk_checker from the validator prompt and run again. Point agentreg.yaml at your own agent when you're ready.

Get the code on GitHub
git clone https://github.com/JYOTSNACHOUDHARY/agent-regression-tester.git
cd agent-regression-tester
uv sync
export OPENAI_API_KEY=sk-...

# run the agent once → trace + test case
uv run agentreg record "healthcare"

# replay every case; exits with 1 on regressions
uv run agentreg run --tools stub --repeats 3
